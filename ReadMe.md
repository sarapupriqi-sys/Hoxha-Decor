# Hoxha Decor

Website for **Hoxha Decor**, a metalwork workshop in Fushë-Krujë, Albania. The workshop designs, forges and installs custom pieces: gates, railings, spiral staircases, windows and grilles, furniture, lighting and accessories, for Albania and abroad.

The site is in Albanian, with a built-in language switcher (English, Italian, Turkish, Greek) powered by Google Translate.

## Features

- **Home page** with a 3D spiral staircase (Three.js) that splits apart on scroll (GSAP ScrollTrigger), a product carousel and a quick request form.
- **Projects** (`/punimet/`): portfolio grid with category filters (`?kat=porta`, `parmak`, `shkalle`, `dritare`, `mobilje`, `ndricues`, `detaje`), a lightbox with previous/next and a "request a quote for this piece" button.
- **Process** (`/procesi/`): the four steps of how the workshop works, with a line that fills on scroll.
- **About**, **Privacy** and custom **404** / **500** pages.
- **Contact** (`/kontakti/`): request form with up to 5 reference photos (JPG, PNG or WebP, 8 MB each, 15 MB total), optional geolocation, and a button that sends the text to WhatsApp. Submissions are saved in the database and emailed to the workshop, with the photos attached.
- **"Kërko Ofertë" modal** on every page: saves the request in the database (`/oferta/`) and opens WhatsApp with a prefilled message.
- Spam protection on both forms (hidden honeypot field).
- SEO: `robots.txt` and `sitemap.txt` generated by Django, Open Graph and Twitter tags, canonical URLs, and LocalBusiness JSON-LD.
- Django admin for reading contact messages and quote requests.

> The `Punim` and `FotoPunimi` models are registered in the admin, but the Projects page is currently static HTML. Photos uploaded in the admin are not shown on the site yet.

## Getting started

Requires Python 3.12 or newer (developed on 3.13) and Git.

```bash
git clone https://github.com/sarapupriqi-sys/Hoxha-Decor.git
cd Hoxha-Decor

python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate

pip install -r requirements.txt

# create a .env file (see "Environment variables" below)

python manage.py migrate
python manage.py createsuperuser    # optional, for /admin/
python manage.py runserver
```

Open <http://127.0.0.1:8000>.

## Environment variables

The settings read a `.env` file in the project root. **Never commit it.** Make sure `.env` is listed in `.gitignore`.

| Variable | Purpose | Default |
|---|---|---|
| `DJANGO_SECRET_KEY` | Django secret key. **Required** when `DJANGO_DEBUG` is off. | none |
| `DJANGO_DEBUG` | `1`, `true` or `yes` turns debug on. | off |
| `DJANGO_ALLOWED_HOSTS` | Comma-separated hosts, for example `example.al,www.example.al`. | `127.0.0.1,localhost` |
| `DJANGO_CSRF_TRUSTED_ORIGINS` | Comma-separated origins with scheme, for example `https://example.al`. | empty |
| `EMAIL_HOST`, `EMAIL_PORT`, `EMAIL_USE_TLS` | SMTP server. | `smtp.gmail.com`, `587`, `True` |
| `EMAIL_HOST_USER`, `EMAIL_HOST_PASSWORD` | SMTP login. For Gmail use an **App Password**, not the account password. | empty |
| `DJANGO_FROM_EMAIL` | Sender address. | `hoxhadecor@gmail.com` |
| `DJANGO_CONTACT_RECIPIENT` | Where contact requests are sent. | `hoxhadecor@gmail.com` |

Example for local development:

```env
DJANGO_SECRET_KEY=generate-a-long-random-value
DJANGO_DEBUG=True
```

Generate a secret key with:

```bash
python -c "from django.core.management.utils import get_random_secret_key as g; print(g())"
```

With `DJANGO_DEBUG` on, emails are printed in the terminal instead of being sent, and the SMTP settings are ignored.

Business details (phone, email, address, hours, WhatsApp and TikTok links) are in `BUSINESS_INFO` in `settings.py`. The same numbers are also written directly in several templates and in `java1.js` (the WhatsApp number).

## Deployment

1. Set the environment variables above on the host: `DJANGO_DEBUG` off (or unset), a real `DJANGO_SECRET_KEY`, `DJANGO_ALLOWED_HOSTS`, `DJANGO_CSRF_TRUSTED_ORIGINS`, and the email settings.
2. Run `python manage.py migrate` and `python manage.py collectstatic --noinput`.
3. Start the app with `gunicorn hoxhadecor_project.wsgi`.
4. Enable HTTPS on the host **before** going live. With debug off, `settings.py` turns on the HTTPS redirect, secure cookies and HSTS (3600 seconds at first; raise it to a year once HTTPS is confirmed to work everywhere). If the host terminates SSL at a proxy, the `X-Forwarded-Proto` header is already trusted.
5. Run `python manage.py check --deploy` with the production variables set. It should report no warnings.

Notes:

- **Static files** are served by WhiteNoise from `staticfiles/`.
- **Uploaded media** (`/media/`) is only served by Django when debug is on. In production it needs Nginx or external storage. This does not affect the site today, because the pages do not use uploaded images.
- **SQLite** keeps all messages and quote requests in the `db.sqlite3` file. On hosts where the disk is wiped on every deploy (many free tiers), these records are lost. Use a persistent disk, or switch to PostgreSQL (this needs a database driver and a change to `DATABASES` in `settings.py`).
- Back up `db.sqlite3` regularly, since it contains customers' names and phone numbers.
